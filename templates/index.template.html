How it works

An aggregator of aggregators.

The problem

Video models like Seedance, Kling, Veo, Wan and MiniMax are sold through many API “aggregators” (fal.ai, Replicate, Atlas Cloud, Runware, Kie.ai and others). Each one sets its own price, runs its own launch sales, and bills in its own units — per second, per clip, per credit, per million tokens. The cheapest place for one model is often the most expensive for another, and it changes week to week.

What this site does

It reads all {{AGG_COUNT}} aggregators every day, converts every quote to the same unit — USD per minute of generated footage at 720p (768p for the MiniMax H3 family) — keeps audio-on and audio-off variants separate, notes each sale and its deadline, and publishes the winner per model. The table at the top is the summary; the charts show the spread; the JSON feed lets software make the choice automatically.

The daily research run

  1. 06:17 New York time, a scheduled job wakes up (GitHub Actions, free).
  2. For every model × aggregator pair it re-opens the provider's own price page — with a headless browser when the page needs JavaScript.
  3. It reads the number with a deterministic pattern first, and falls back to Claude reading the page (and, if the page moved, searching the provider's site) so a redesign does not break the feed.
  4. Every figure is normalized to $/min, sanity-checked against yesterday (a 5× jump is flagged, not published), and dated sales that ended are switched to the regular price.
  5. It recomputes the cheapest aggregator per model, writes a dated snapshot for the history charts, rebuilds this page and publishes it.

{{LAST_RUN}}

Reading the numbers honestly

“Per minute” means accumulated generated footage, not one continuous 60-second clip — the Max clip column shows the longest single clip each endpoint allows. Prices for token-billed models are estimates for a 16:9 output at the stated resolution. Provider-specific tiers (Kie's “Lite mode” for Veo, Atlas's “Developer” tier for Grok) are kept as their own rows because they are not guaranteed to be the same product as the standard API. Quality is not ranked here — only price. Every quote links to its source, carries the date it was verified, and is flagged when the robot could not re-verify it.

Endpoints

GET {{SITE_URL}}data/cheapest.jsonPer model: cheapest aggregator, API base URL, endpoint id, $/min, promo deadline. Small — fetch this.
GET {{SITE_URL}}data/prices.jsonEverything: all quotes across all aggregators, raw billing text, sources, verification verdicts, deals.
GET {{SITE_URL}}data/history/index.jsonList of daily snapshots (then history/YYYY-MM-DD.json).
GET {{SITE_URL}}data/changes.jsonWhat changed, when, and why (price moves, sales that ended).
GET {{SITE_URL}}llms.txtPlain-text instructions for language models.

Everything is static JSON over HTTPS, no key, no rate limit beyond GitHub Pages' generosity, CORS-open. It refreshes once a day; cache it for an hour and you are fine.

Routing recipe — “render this with my favourite model, wherever it's cheapest today”

Python

import requests

FEED = "{{SITE_URL}}data/cheapest.json"
feed = requests.get(FEED, timeout=10).json()

best = feed["models"]["mini"]          # Seedance 2.0 Mini (ids are in the feed)
print(best["cheapest_aggregator"],       # e.g. "Atlas Cloud"
      best["usd_per_min_720p"],          # e.g. 1.45
      best["endpoint_id"])               # the model id to pass to that API

# Now call that aggregator's API:
api = best["aggregator"]["api_base_url"]
docs = best["aggregator"]["api_docs_url"]
# → build the request per `docs`, using best["endpoint_id"]

JavaScript / Node

const FEED = "{{SITE_URL}}data/cheapest.json";
const feed = await (await fetch(FEED)).json();

const wanted = "Kling 3.0 Turbo";
const [id, best] = Object.entries(feed.models)
  .find(([, m]) => m.model === wanted);

            best.endpoint_id, best.aggregator.api_base_url);
// estimate for a 15 s clip:
const clipUsd = best.usd_per_min_720p * 15 / 60;
